## Migration table as implemented

| Input | Effective interpretation on read |
| --- | --- |
| Scan unversioned legacy, 2.0, 2.1, 2.2 or 2.3 with established Explorer provenance and `HDA:3` | `DATE_DMY_U8X3` on the copy. |
| Same versions/provenance with `HTI` | `TIME_HMS_U8X3` on the copy. |
| Known application baseline integer 1 with those labels | Same neutral interpretation on the copy. |
| External or unknown-source BCD labels | No migration. Distinct labels remain unsupported raw evidence. An explicit external producer takes precedence over a copied Explorer contract. |
| Legacy Explorer type overrides | Neutral interpretation on the copy; retain original labels and override paths separately in `meta.type_override_migrations`. |
| Numeric API observations | Normalize each independently to its string form, e.g. numeric `1.0` becomes raw string `"1"`; retain numeric fields. |
| `API1` label alone or missing independently observed revision | Display label only; no complete identity or reuse qualification. |
| Contradictory numeric/raw API dimension | Retain contradictory evidence with `api_identity_conflicts`; reject profile qualification and write preparation. |

Established scan provenance means one of:

- explicit `meta.producer: helianthus-vrc-explorer`;
- the retained Explorer artifact contract (`opcode_hex`, `presentation_only`,
  and the namespace-aware `<group>:<operation>:<instance>:<register>` key);
- the existing Explorer replay pair: `meta.schema_sources` includes
  `replay_trace:enhanced_v1` and `meta.replay_trace.format` is `enhanced_v1`.

A version number, family identity, or calendar codec label alone is insufficient.
Known baseline provenance means the packaged application baseline, or an external
v1 row retaining `source: read_only_observed_baseline` and an established Explorer
`b524-description/v1` or `/v2` decoder revision. Unknown-source rows are not guessed.

Each migrated row/description retains application-only `codec_migration` with
`source_label`, `source_version`, and `source: helianthus-vrc-explorer`. Original
raw/reply bytes and stored decoded values are untouched. Interpretation does not
re-decode historical values. Opening files never rewrites them. Native CC0
serialization must keep this application provenance outside the native schemas.

Legacy baseline/scan examples remain inline in migration tests; committed native
fixture JSON files were not changed.
